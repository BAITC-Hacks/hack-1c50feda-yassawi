# Методика этапа 1

Изменение политики зафиксировано до сравнений в `experiment_plan.json`: SHA-256 обеих версий, основной диапазон seed 0–99 и дополнительный 100–149. Параметры не изменяются по результатам этих прогонов. Исторический top-3, модель каналов, штраф риска и жадный отбор финала остаются прежними.

## Что изменено

Первые шесть успешных пилотов по-прежнему ориентированы на разнообразие аудиторий. Далее рассматриваются как непроверенные гипотезы, так и неоднозначные повторные проверки. Оба вида конкурируют по одной оценке ценности, а не по разрешению фиксированной фазы. Она вычисляется только из публичных наблюдений агента.

Обозначения: `mu` и `v` — текущее среднее и дисперсия эффекта для отдельного канала, `A` — сумма predicted_arpu сегмента, `N` — размер аудитории, `c` — стоимость контакта, `n` — размер предлагаемого пилота. После него `v_new = 1 / (1/v + n/0.804²)`. В принятой нормальной модели будущее апостериорное среднее имеет математическое ожидание `mu` и дисперсию `v - v_new`.

Пусть `B` — максимум нуля и текущего консервативного прогноза проверенных альтернатив для той же аудитории. Тогда:

```text
d = mu*A - N*c - A*sqrt(v_new) - B
s = A*sqrt(v-v_new)
expected_surplus = s*phi(d/s) + d*Phi(d/s)
current_surplus = max((mu-sqrt(v))*A - N*c - B, 0)
value = expected_surplus - current_surplus - n*(c + opportunity_per_contact)
```

`phi` и `Phi` — плотность и функция распределения стандартной нормали. При `s=0` берётся `max(d,0)`. `opportunity_per_contact` — лучший положительный консервативный прогноз проверенной доступной кампании, делённый на остаток контактов. Приоритет положительной ценности дополнительно уменьшается при большом расходе оставшегося бюджета. При равных оценках предпочтение получает ещё не проверенная ячейка, затем стабильный индекс кандидата.

Это эвристика ожидаемого улучшения **самостоятельного консервативного прогноза финала**. Она не рассчитывает истинную ценность эксперимента с учётом будущих действий, эффектов самого пилота и пересечений с пилотами. Штраф `mean - std` не является гарантией прибыли. Известная ранее граница 2.5σ для уже достаточно определённых повторов сохранена. Резервируется самая дешёвая целая кампания: это сохраняет допустимый финал, но может завышать ценность проверки другой, более крупной аудитории.

## Остановка

В журнале фиксируется `pilot_stop` с отдельной причиной:

- `insufficient_resources` — допустимый пилот не помещается в остатки с резервом финала;
- `no_estimated_value` — нет положительной ценности по политике, включая отсечение достаточно определённых повторов;
- `search_space_exhausted` — заданные кандидаты исчерпаны, недоступны после ошибок или повторных проверок;
- `internal_pilot_limit` — достигнут внутренний предел 16 попыток;
- `environment_pilot_limit` — исчерпаны пилоты среды;
- `timeout` — достигнут предел времени.

При пустом списке доступных выборов записывается также число отсечений по ресурсам, пространству поиска и ценности: одна причина остановки не скрывает смешанные причины отказов. Размер и количество пилотов не фиксируются на 20.

## Внешняя оценка

`split_eval.py` создаёт отдельную среду для каждой пары версия/seed и вызывает `act()` ровно один раз. Только после возврата получает внутренние ID уже проведённых пилотов и модель для официального оценщика. Вычисляются три независимых сценария с теми же выполненными пилотами:

- `net_pilots_only`: пилоты;
- `net_combined`: пилоты и возвращённый финал;
- `net_final_standalone`: только финал.

`final_incremental_net = net_combined - net_pilots_only`. Самостоятельный финал не прибавляется к пилотам: это нарушило бы дедупликацию пересекающихся клиентов. `forecast_final_mean_net` и `forecast_final_risk_adjusted_net` берутся из журнала, отдельно от всех четырёх фактических метрик. Обратного вызова агента после скоринга нет.

Проверяются валидность кампаний, все размеры и затраты до скоринга, точное списание пилотных ресурсов, отсутствие отброшенных и обрезанных кампаний. Время `act_seconds` отделено от внешней оценки и полного запуска. Порядок запуска версий чередуется, чтобы снизить систематическое преимущество первой версии при измерении времени.

Оба набора seed используют одну мок-модель эффектов. Различаются выборки и шум, а не модели поведения. Дополнительный диапазон не используется для настройки.

## Границы этапа

Расширение за пределы исторического top-3, обмен информацией между каналами и переносимость прежнего `verify_artifacts.py` оставлены следующим отдельным этапам. UI и LLM не изменены. Исходные CSV и файлы организаторов сверяются с прежним манифестом, новый эталон для них не создаётся. Снимок `snapshots/before_stage1` проверяется по хешам до и после сравнения и загружается без записи `__pycache__`.
