# BeeGrowth Agent: двухминутная демонстрация

Показываем **основную восстановленную стратегию** из корневого `agent.py`. Её SHA-256: `76deffc4d074b85f0453977e422dd64b7ab6257febb1f40f0f0f714734def1cc`. Все приведённые ниже числа — сохранённые локальные результаты стабилизации на синтетических данных при `seed=42`, а не обещание прибыли или балла судейства.

## Перед показом

1. Установите зависимости по [README.md](README.md). Из корня проекта запустите:

   ```powershell
   .\.venv\Scripts\python.exe -m streamlit run demo_app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
   ```

2. Откройте `http://127.0.0.1:8501` на том же компьютере. Сервер доступен только локально, браузер автоматически не открывается. Оставьте `Seed новой независимой мок-среды` равным **42**. Нажмите **«Запустить агента»** заранее, чтобы проверить запуск. Во время показа можно повторить запуск с тем же seed; новые seed для этого сценария не нужны.
3. Откройте в редакторе [diagnostics/stabilization/main_split_seed42.json](diagnostics/stabilization/main_split_seed42.json) и корневой [submission.csv](submission.csv). В JSON найдите `agent_sha256`, `net_pilots_only`, `net_combined` и `final_incremental_net`. Отдельной карточки добавочного вклада финала в интерфейсе нет — этот показатель показываем из сохранённой раздельной диагностики.
4. Перед показом убедитесь, что доступен терминал с рабочим каталогом в корне проекта. Подготовка и ожидание запуска браузера не входят в две минуты выступления. После показа остановите демо сочетанием `Ctrl+C` в терминале, где оно запущено.

После безопасной очистки повторно прошли общие тесты и тесты демо, официальный seed=42 дал PASS, а два запуска генератора создали побайтово одинаковый CSV. Повторная раздельная оценка подтвердила показанные ниже общий net и отрицательный вклад финала. Локальный сервер ответил HTTP 200 на страницу и health endpoint. AppTest проверил аудиторию, четыре вкладки, 16 пилотов, одну кампанию, прогноз и оценку, отсутствие повторного запуска агента при переключении этапа, создание CSV и две кнопки скачивания. Визуальный просмотр и скачивание через реальный браузер не проверялись. [Итоговый протокол](diagnostics/final_verification/report.md), [сценарий AppTest](diagnostics/final_verification/demo_scenario.json).

## Официальный CSV через терминал

Эквивалент кнопки создания CSV, из корня проекта:

```powershell
.\.venv\Scripts\python.exe make_submission.py
Get-Content -Encoding UTF8 .\submission.csv
```

Скрипт заново создаёт корневой `submission.csv` с `seed=42`. Seed, выбранный для отдельного демо-запуска, не меняет официальный seed. В подтверждённом файле:

```csv
campaign_name,filter_arpu_segment,filter_data_segment,filter_call_segment,filter_current_tariff,target_tariff,channel
BeeGrowth_01,HIGH,,,tariff_10,tariff_14,push
```

## Ответы на ожидаемые вопросы

- **Откуда числа?** План, прогноз, 16 пилотов и раздельные результаты зафиксированы в [main_split_seed42.json](diagnostics/stabilization/main_split_seed42.json) с хешем основной версии. Проверки лимитов, официального запуска и повторяемости описаны в [отчёте стабилизации](diagnostics/stabilization/report.md). Если свежий запуск не совпал, показывайте сохранённые числа именно как результат этой проверки, а расхождение исследуйте отдельно.
- **Почему прогноз выше результата?** Прогноз основан на истории и шумных пилотах. Он не учитывает пересечения с уже проведёнными пилотами так же, как локальный оценщик; это ограничение текущей версии. Прогноз не является фактическим результатом и не гарантирует прибыль.
- **Почему вклад финала отличается от его отдельной оценки?** `final_incremental_net = net_combined − net_pilots_only`. Оценка одного финала `net_final_standalone` равна **−7 081,57**; это другой сценарий, без пилотов. Оценщик учитывает пересечения аудиторий и дедупликацию эффекта, поэтому эти величины нельзя подменять друг другом.
- **Как объяснить решение?** На вкладке **«Объяснения»** доступны этапы: «Гипотезы из сглаженной истории», «Проверки и обновление оценок», «Выбранные кампании», «Отказы», «Остатки ресурсов». Можно нажать **«Скачать отчёт запуска JSON»**. Этот отчёт демо содержит общий результат; раздельный вклад финала находится в отдельном файле диагностики, указанном выше.
- **Что пока ограничивает основную стратегию?** Поиск большинства новых гипотез ограничен после первых шести проверок; в контролируемом сценарии шести отрицательных пилотов основная версия прекращает поиск. Также сохранены исторический top-3 тарифов, независимые оценки каналов, жадный выбор финального плана и резервная стратегия, которая не гарантирует положительный net. Исправление контролируемого поведения есть в [архиве stage1](experiments/stage1_expanded_search/README.md), но его финансовые результаты на проведённом сравнении ухудшились. Основной запуск не использует этот архив.

Не называйте локальные результаты доказательством реальной прибыли, прибыльности каждой кампании или определённого балла судейства. Во время показа не смешивайте прогноз, оценку общего плана и добавочный вклад финала.
