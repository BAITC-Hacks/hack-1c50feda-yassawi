# BeeGrowth Agent

Проект HackAlem AI для кейса Beeline Tariff Marketing Campaigns. Пользователь — маркетинговый аналитик: агент исследует гипотезы пилотами и выбирает до 10 тарифных кампаний под общий бюджет. Цель — дополнительный ARPU по уникальным абонентам минус стоимость всех контактов.

Все данные синтетические. Это не показатели Beeline. Мок-оценка проверяет механику и устойчивость, но не гарантирует результат скрытого судейства.

## Установка и запуск в Windows / PowerShell

Проверено на Python 3.14.6. В текущей системе рабочий интерпретатор найден в `D:\anaconda\python.exe`; команда `python` указывала на недоступный Windows alias (`The file cannot be accessed by the system`). Для другой машины замените путь на установленный Python.

```powershell
& 'D:\anaconda\python.exe' -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe local_eval.py
.\.venv\Scripts\python.exe local_eval.py --runs 10
.\.venv\Scripts\python.exe make_submission.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe audit_data.py
.\.venv\Scripts\python.exe benchmark.py
.\.venv\Scripts\python.exe verify_artifacts.py
.\.venv\Scripts\python.exe -m streamlit run demo_app.py
```

Команды выполняются из корня репозитория. Активация окружения не требуется. Установка зависимостей требует доступа к PyPI; сам агент, оценка и демо работают без интернета и API-ключей. Первая установка в ограниченной среде получила WinError 10013; повторная установка с разрешённым сетевым доступом завершилась успешно, глобальные пакеты не менялись. Streamlit нужен только для демо и его теста.

## Интерфейс и состав

`agent.py` содержит весь вычислительный алгоритм: `Agent().act(env) -> list[dict]`. Он читает только публичные профиль, тарифы, каналы и остатки ресурсов, вызывает `env.run_pilot`. История берётся из `data/change_tariff.csv` относительно `agent.py`. При её отсутствии используется слабая гипотеза по цене тарифа; прошлые пилоты с диска не загружаются.

Возвращаются только официальные поля: имя, целевой тариф, канал и четыре разрешённых фильтра. Несколько текущих тарифов разделяются `;`. Нет `explicit_ids` и фиктивного ограничения размера финальной кампании. `Agent(log_path='diagnostics/decisions.json')` дополнительно сохраняет журнал; ошибки записи не прерывают работу. Журнал всегда доступен как `agent.log`.

Другие файлы: `audit_data.py` — аудит CSV, `benchmark.py` — сравнение с неизменённым шаблоном, `verify_artifacts.py` — проверка артефактов и лимитов, `tests/` — тесты, `demo_app.py` — интерфейс, `diagnostics/` — фактические результаты. `organizer_hashes.json` фиксирует SHA-256 исходных файлов до работы. Удалены только разрешённые `server.py` и `index.html` предыдущего проекта.

## Гипотезы и обработка данных

1. Базовые ячейки: `current_tariff × arpu_segment`; размер и сумма `predicted_arpu` вычисляются из профиля. Ячейки свыше 5000 последовательно разбиваются по `data_segment`, затем `call_segment`. Если это не даёт допустимую аудиторию, ячейка исключается. Пропущенные ключи сегментации не превращаются в фильтр «вся база».
2. В истории удаляются полные дубликаты в памяти. Строки с нечисловым/нефинитным ARPU, исходным ARPU <= 0 или последующим ARPU < 0 исключаются. Относительное изменение ограничивается диапазоном [-1, 2], чтобы малый знаменатель не определял весь выбор.
3. Среднее условное изменение после перехода сглаживается 30 псевдонаблюдениями слабой гипотезы по цене. Для каждой ячейки выбираются три целевых тарифа, затем рассматриваются доступные каналы. Список тарифов не зашит. Частота переходов не трактуется как конверсия: в истории нет знаменателя отправленных предложений.
4. Начальная вероятность отклика 0.15 — явно заданное слабое предположение, а не измеренная конверсия. Коэффициент канала применяется только к этому начальному предположению с ограничением вероятности до 1. Наблюдение пилота уже относится к каналу и повторно не умножается.

Нулевой `predicted_arpu` разрешён, отрицательные/нефинитные значения приводят к исключению всей выражаемой фильтрами ячейки: нельзя удалить отдельные строки из финального охвата, оставив прежний фильтр. История и профиль не соединяются по ID: это разные выборки. Таблицы месячного ARPU и трафика проверяются аудитом, но для обучения не используются.

## Пилоты и неопределённость

Для каждой пары «аудитория, целевой тариф, канал» хранится отдельная нормальная априорная оценка эффекта со стандартным отклонением 0.20. Для пилота с фактическим размером n дисперсия наблюдения равна `0.804² / n`: 0.804 указан в публичной среде. Обновление normal-normal:

```text
precision_new = precision_old + n / 0.804²
mean_new = (precision_old * mean_old + n / 0.804² * observed_lift_ratio) / precision_new
variance_new = 1 / precision_new
```

Это модельная апостериорная неопределённость при нормальном независимом шуме. Поправка `mean - std` — критерий риска, не обещание доверительного покрытия на скрытой аудитории. Систематическое смещение истории и неоднородность клиентов полностью этой моделью не описываются.

Сначала агент исследует до шести разных ячеек. Далее проверяет альтернативные каналы двух текущих лидеров и уточняет уже наблюдавшиеся неоднозначные гипотезы. Приоритет включает оптимистичный чистый эффект, уменьшение неопределённости, размер аудитории и денежную ограниченность. Ценность проверки уменьшается на стоимость контактов и оценку их упущенной выгоды.

Начальный пилот — 100 человек. Для повторного пилота рассчитывается число новых наблюдений до модельного std 0.05, затем размер ограничивается диапазоном 100–200, фактической аудиторией и ресурсами. Используется возвращённое средой n, даже если оно меньше запрошенного. Уже достаточно определённые гипотезы не перепроверяются; отрицательное шумное наблюдение само по себе не означает немедленный отказ.

Внутренний потолок — 16 пилотов, до трёх на гипотезу; раньше агент останавливается при отсутствии ценной/доступной проверки. Размер и число действительно зависят от наблюдений: это проверяется отдельным контролируемым тестом. Перед каждым вызовом резервируются контакты и деньги на целую допустимую финальную кампанию. Остатки берутся из среды без повторного вычитания пилотных расходов. Порядок и разрешение равенств стабильны; собственный RNG фиксирован, текущий алгоритм не требует случайной выборки. Новое `act()` сбрасывает журнал и оценки.

## Финальное распределение ресурсов

Прогноз кампании: `mean × сумма predicted_arpu − стоимость канала × размер`. Жадный алгоритм повторно выбирает положительный риск-скорректированный добавочный результат с поправкой на расход оставшихся денег и контактов. Для масштабирования требуются пилот и положительное значение `mean - std`. Финальные аудитории не пересекаются; стоимость каждого полного фильтра учитывается заранее, обрезка оценщиком не используется.

Если положительного варианта нет, выбирается допустимая кампания с максимальным риск-скорректированным результатом как резервный план с возможным убытком. Это явно отмечается в журнале. Если исходная среда пуста или ни одна выражаемая аудитория не помещается в ресурсы, возвращается пустой список с причиной `infeasible`: требование 1–10 кампаний математически невыполнимо для таких входов. На всех проверенных официальных средах возвращены 1–10.

Повторные пилотные контакты и пересечение пилотов с финальными аудиториями тратят ресурсы. Агент не прибавляет прогноз пилотов к прогнозу финала: без публичных ID нельзя точно предсказать их объединение. Официальный оценщик отдельно считает эффект по уникальным клиентам. Его внутренние данные агенту не передаются. Выбор жадный, глобальный оптимум не гарантирован; три исторически выбранных тарифа могут пропустить перспективный неизвестный вариант.

## Фактические проверки

Выполнены официальный одиночный прогон, `--runs 10`, два запуска `make_submission.py`, сравнение SHA-256, тесты, аудит, сравнение с шаблоном и проверка артефактов. Результаты последней версии:

| Агент, seed 0–9 | Медиана net | Минимум | Максимум | Положительных | Время 10 оценок |
| --- | ---: | ---: | ---: | ---: | ---: |
| BeeGrowth | 312816 | 31242 | 505986 | 10/10 | 14.44 с |
| agent_template | -357948 | -1019431 | -76493 | 0/10 | 5.87 с |

Это подтверждённое локальное превосходство над шаблоном, не прогноз скрытых эффектов. Для seed=42: `PASS`, net +13742, расходы 8918, контактов 4722, 16 пилотов и одна финальная кампания. Финальная кампания сама может оказаться убыточной при шумной разведке: положительный итог здесь включает пилоты. Гарантии прибыли нет.

10 автоматических тестов прошли, включая официальный контракт, лимиты, непересекающиеся аудитории, большие/пустые сегменты, пропуски, отрицательные и шумные наблюдения, фактическое n, изменение решений, адаптивность числа/размера пилотов, воспроизводимость без API-ключа, ошибки пилотов/журнала и Streamlit rerun. Streamlit проверен через AppTest: запуск, повторное выполнение, независимый новый запуск, создание submission. Визуальная проверка в браузере не проводилась.

`diagnostics/benchmark.json` содержит результаты и время каждого seed. `diagnostics/verification.json` проверяет лимиты seed 0–9 и 42, воспроизведение submission и неизменность 15 файлов организаторов. `diagnostics/decisions_seed42.json` — журнал решений. `diagnostics/submission_sha256.txt` — контрольная сумма двух одинаковых официальных генераций.

## Демо и сдача

```powershell
.\.venv\Scripts\python.exe -m streamlit run demo_app.py
```

Демо показывает аудиторию, отдельно прогноз агента, шумные наблюдения, локальный скоринг и журнал. Результат хранится в `session_state`: изменение seed/вкладок не запускает пилоты, только кнопка запуска создаёт новую среду. Есть экспорт JSON. Отдельная кнопка запускает неизменённый `make_submission.py` и предлагает скачать официальный CSV с seed=42; он может отличаться от выбранного демо-seed.

`submission.csv` лежит в корне и создан только официальным скриптом. Для сдачи приложите `agent.py`, `submission.csv`, `requirements.txt`; исторические CSV уже входят в комплект организаторов. Агент не импортирует Streamlit, оценщик или приватные мок-функции. Коммиты и push не выполнялись.
