# QADAM · Campaign Lab

**HackAlem AI / Beeline кейсіне арналған пилоттан үйренетін науқан агенті және қазақша интерфейс.**

Мақсаты: ARPU-ды арттыратын науқандарды таңдау, байланыс құнын шегеру, пилот белгісіздігін ескеру және ортақ лимиттерден шықпау. Жоба статистикалық агентке сүйенеді; LLM, API кілті және ақылы сервис қажет емес.

> Барлық деректер синтетикалық. Бұл нақты Beeline бизнесінің көрсеткіштері емес. Ресми mock ортадағы нәтиже жасырын финалдағы баллға кепілдік бермейді. Бағдарлама нақты адамдарға хабарлама жібермейді.

Ортақ репозиторийдің негізгі агенті — QADAM. Қазақша интерфейс `server.py` арқылы ашылады. Бұрынғы Streamlit интерфейсі де QADAM есебімен жұмыс істеуге бейімделді: `python -m streamlit run demo_app.py`. `verify_artifacts.py` ұйымдастырушы файлдарының тұтастығын, submission қайталануын және лимиттерді тексереді; `benchmark.py` QADAM-ды шаблонмен салыстырады. `diagnostics/` ішіндегі бұрын сақталған есептер алдыңғы агентке қатысты болуы мүмкін; QADAM тексеру нәтижелері `docs/VALIDATION.md` ішінде берілген.

## Ең оңай іске қосу

1. Толық ZIP архивін шығарыңыз. Жоба қалтасында `agent.py`, `server.py`, `customer_profile.csv`, `data/` болуы керек.
2. **Windows: `start.bat` файлын іске қосыңыз.** Алғашқы іске қосуда Python 3.11+ және тәуелділіктерді орнату үшін интернет керек. Осы компьютерде Codex-тің Python runtime-ы да автоматты табыла алады.
3. Терминалда `QADAM ready` шыққаннан кейін **http://127.0.0.1:8765** мекенжайын ашыңыз.
4. «Агентті іске қосу» батырмасын басыңыз. Қажет болса «10 seed-пен тұрақтылықты тексеру» белгісін қосыңыз.
5. «Науқандар» бөліміндегі **«Неге?»** түсіндірмесін қараңыз. Жоспар CSV және аудит JSON экспорттаңыз.

Сервер жұмыс істегенде терминалды ашық қалдырыңыз. Тоқтату: Ctrl+C. Порт бос болмаса: `start.bat --port 8766`, содан кейін http://127.0.0.1:8766 ашыңыз.

Қолмен, PowerShell арқылы:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

macOS/Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py
```

Орнатудан кейін сервер мен агент интернетсіз жұмыс істейді. Linux/macOS командалары берілген, бірақ осы жеткізілім Windows-та тексерілді. Тәуелділіктердің нұсқалары `requirements.txt` ішінде бекітілген.

## Visual Studio Code

1. **File → Open Folder** арқылы жоба қалтасын ашыңыз.
2. Microsoft Python және Python Debugger кеңейтімдерін орнатыңыз.
3. **Python: Select Interpreter** арқылы `.venv\Scripts\python.exe` таңдаңыз.
4. **Run and Debug → QADAM: dashboard → F5**.

`.vscode/launch.json` ішінде dashboard, 10 seed бағалауы және submission жасау профильдері бар. [VS Code-тың ресми Python ортасы нұсқаулығы](https://code.visualstudio.com/docs/python/environments).

## Visual Studio (толық IDE)

1. Visual Studio Installer ішінде **Python development** компонентін таңдаңыз.
2. `Qadam.sln` шешімін ашыңыз.
3. **Python Environments** бөлімінде Python 3.11+ немесе жоба `.venv` ортасын таңдаңыз; `requirements.txt` тәуелділіктерін орнатыңыз.
4. `server.py` startup file ретінде берілген. Ctrl+F5 арқылы іске қосып, браузерде жергілікті мекенжайды ашыңыз.

Бұл Python web-интерфейсі, C# WinForms емес: хакатонның міндетті `Agent.act(env)` келісіміне сай жасалды. IDE конфигурациялары қосылған; Visual Studio GUI-інде F5 осы ортада жеке тексерілген жоқ. [Microsoft-тың Python жобалары нұсқаулығы](https://learn.microsoft.com/en-us/visualstudio/python/managing-python-projects-in-visual-studio).

## Міндетті хакатон тексерулері

Командаларды жоба түбірінде, тәуелділіктер орнатылған Python-мен орындаңыз:

```bash
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
python -m unittest discover -s tests -v
```

Windows-та `python` командасы жоқ болса, оның орнына `.\.venv\Scripts\python.exe` қолданыңыз.

**Тапсыратын файлдар:** `agent.py`, `submission.csv`, `requirements.txt`. `data/change_tariff.csv` агентке гипотезаларды ранжирлеуге көмектеседі; ұйымдастырушы пакетте ол бар. Файл жоқ болса, бейтарап барлау іске қосылады, бірақ бұл жағдайда нәтижесі бөлек болады.

`submission.csv` өзгертілмеген ұйымдастырушының `make_submission.py` командасымен, **seed 42, risk 1.28, 20 пилот** әдепкі параметрлерімен жасалады. Интерфейстегі басқа параметрлермен экспортталған `campaign-plan-seed-*.csv` файлын ресми submission орнына жай ауыстырмаңыз. Соңғы тапсыру алдында міндетті команданы қайта орындаңыз.

Ұйымдастырушының `environment.py`, `mock_environment.py`, `scoring_core.py`, `local_eval.py`, `make_submission.py` файлдары өзгертілген жоқ. Агент жасырын модельді, scoring ішкі күйін немесе mock ішкі атрибуттарын оқымайды. Dashboard ресми `evaluate_agent` функциясын тек нәтижені көрсетуге қолданады; оның қорытындысы агентке кері берілмейді.

## Әдіс және ерекшелігі

1. **History for ordering, pilots for decisions.** Басқа аудиториядағы тарихи ауысулар бағыттарды ранжирлейді. Өте төмен бастапқы ARPU және шеткі қатынастар сүзгіленеді. Шағын топтар жұмсартылып бағаланады. Тарих posterior орташа мәніне енгізілмейді.
2. **Қамтуды әртараптандыратын барлау.** Алғашқы пилоттар түрлі current_tariff × ARPU сегменттерін қамтиды; әр сегментте үш балама мақсат қарастырылады. Қажет жерде data/call сегменттері 5 000 шегін сақтау үшін қолданылады.
3. **Белгісіздікке бейімделетін қайта тексеру.** Жоғарғы ықтимал әсері жоғары сегменттерге қайта пилот жасалады; үлгі көлемі белгісіздікке тәуелді өзгереді. Қауіпсіз жорамалмен оң көрінген бағытта қолжетімді ақылы канал да сыналуы мүмкін.
4. **Сақ портфель.** Орташа әсерден `z × standard_error` шегеріледі. Канал көбейткіші мен байланыс шығыны есептеледі. Финалдық сегменттер қиылыспайды; beam search ақша, контакт және науқан санын бір уақытта тексереді.
5. **Шешім паспорты.** Әр науқанда пилот саны, болжам, сақ баға, шығын және каналдың шынымен сыналғаны көрсетіледі. CSV жоспар мен JSON есеп кодтың шешімін тексеруге мүмкіндік береді.

Бұл компоненттердің осы кейске бейімделген үйлесімі жобаның ерекшелігі. Математикалық әдістердің өздері жаңа ғылыми жаңалық немесе әлемде жалғыз тәсіл ретінде ұсынылмайды.

Толық мәселе талдауы: [docs/CASE_ANALYSIS.md](docs/CASE_ANALYSIS.md). Тексеру нәтижелері: [docs/VALIDATION.md](docs/VALIDATION.md).

## Шектеулерді дұрыс түсіну

- Бюджет 100 000; контакт 15 000; пилот 20; пилотта 10–200; финалдық науқан 1–10; бір науқанда ≤5 000.
- Әрбір нақты ресурс тексерісі жуық емес. Бірақ портфельдің оптимизациясы **жуық**; жаһандық максимумға кепілдік жоқ.
- Posterior қалыпты шу моделіне сүйенеді. `.9 / sqrt(n)` шу масштабы жария template-дегі «n=150 үшін std≈0.07» бағасына консервативті түрде жақындатылған. Ол жасырын ортада калибрленген емес.
- Канал арасындағы ауыстыру қоғамдық multiplier-ге сүйенеді. Басқа каналдың әсері жеке тестсіз дәлелденді деп көрсетілмейді.
- Бірде-бір сақ оң нұсқа болмаса, кейстегі «кемінде 1 науқан» талабын орындау үшін сыналғандардың ықтимал шығыны ең аз қолжетімді нұсқасы қайтарылады. Ескерту шығарылады; пайда кепілденбейді. Ресурс/пилот қатесі кезінде жарамды нұсқа болмаса, лимитті бұзбай бос жоспар қайтуы мүмкін.
- Пилот шығындары және барлық контакт саны есептеледі. Финалдық болжамға пилот өсімі қосылмайды: олардың аудиториясы қиылысуы мүмкін. Нақты жергілікті қорытындыны ресми evaluator дедупликациямен есептейді.
- Пилот үлгілерінің ID-лары агентке ашылмайды. Қайталанған пилоттардың тәуелсіздігі толық кепілденбейді; posterior сенімділігі оптимистік болуы мүмкін.
- Сервер — тек осы компьютерге арналған local demo, көп пайдаланушыға ашық production сервис емес. Авторизация, пайдаланушы рөлдері және production дерекқоры жоқ.

## GitHub-қа жүктеу

**Алдымен private репозиторий жасаңыз.** [GitHub visibility құжаттамасы](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/setting-repository-visibility) public репозиторийдің кодын барлығы көре алатынын түсіндіреді. Private режим көшіріп алуға құқық берілген адамның әрекетін толық тоқтатпайды; ашық жарияланған кодты техникалық түрде «ұрланбайтын» ету мүмкін емес. Идеяның тек сізге ғана берілетініне кепілдік жасалмайды.

Бұл жоба сыртқы GitHub аккаунтына автоматты жүктелген жоқ. Жергілікті Git-ті бастаңыз:

```bash
git init
git add .
git status --short
git commit -m "Add QADAM campaign lab"
git branch -M main
```

GitHub-та бос **private** repository жасаңыз; оның өз URL-ын көшіріп, `git remote add origin YOUR_REPOSITORY_URL` және `git push -u origin main` орындаңыз. Құпия токенді кодқа, URL-ға немесе чатқа салмаңыз; Git Credential Manager/GitHub Desktop қолданыңыз.

`.gitignore` қатысушы деректерін, ұйымдастырушы файлдарын, runtime, `.venv`, кілттерді Git-тен алып тастайды. Сондықтан GitHub-тан clone жасаған адам **өзінің қатысушы ZIP-ін жоба түбіріне шығарып** барып ресми бағалау мен dashboard-ты іске қосады. Толық жергілікті ZIP ішінде олар ыңғайлы іске қосу үшін бар; оны public attachment ретінде жүктемеңіз.

GitHub Actions тек дерексіз core тесттерін орындайды. Ресми бағалау ұйымдастырушы материалдары бар компьютерде орындалады. Құқық туралы нақты құжат берілмеген ұйымдастырушы материалдарына өз лицензиямызды қолданбаймыз; жариялау талаптарын ұйымдастырушымен нақтылаңыз.
