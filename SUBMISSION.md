# Комплект BeeGrowth и порядок отправки

Основная версия — корневой `agent.py` с SHA-256 `76deffc4d074b85f0453977e422dd64b7ab6257febb1f40f0f0f714734def1cc`. Алгоритм при финальной подготовке не менялся. Инструкция запуска — в [README.md](README.md), сценарий показа — в [DEMO.md](DEMO.md).

## Состав репозитория

- Основной агент, актуальный официальный `submission.csv`, `requirements.txt`, демо, модули среды и исходные данные. Предоставленные организаторами файлы уже отслеживаются Git и сохранены без правок.
- README, DEMO, этот документ, все тесты и `tests/README.md`, внешнюю раздельную диагностику и инструменты аудита.
- `diagnostics/stabilization/` как историческое подтверждение восстановленной версии; `diagnostics/stage1/` как исторический результат непринятого эксперимента; `diagnostics/submission_prep/` как проверку комплектности на предыдущем этапе подготовки; `diagnostics/final_verification/` как протокол повторных проверок после безопасной очистки. Старые корневые отчёты в `diagnostics/` сохраняются со своим происхождением.
- **Целиком** `snapshots/before_stage1/` и `experiments/stage1_expanded_search/`, включая их манифесты, историю и отчёты. Снимок, эксперимент и исходные результаты stage1 суммарно занимают около 8.1 МБ. Полные архивы позволяют проверить хеши и запустить сохранённые экспериментальные тесты. Удаление отдельных дублирующих файлов нарушит их манифесты.
- `.gitignore` и `.gitattributes`. Правила `-text` сохраняют байты файлов с контрольными суммами независимо от `core.autocrlf`. Они не изменяют содержимое рабочих файлов. `submission.csv` и `organizer_hashes.json` могут появиться в разнице Git из-за сохранения существующих CRLF вместо нормализации в LF.

Основная версия и демо не требуют архивов при запуске. Полный набор исторических тестов требует их присутствия. Личные абсолютные пути внутри старых отчётов — сведения о месте проверки, а не настройки запуска. `.venv` создаётся заново на машине получателя.

## Что оставить локально

Не включать `.venv`, `.env`, `.env.*`, `.streamlit/secrets.toml`, ключи `*.pem`/`*.key`, `__pycache__`, `*.pyc`, `*.pyo`, `.pytest_cache` и `*.tmp`: для них настроен `.gitignore`. `.env.example` допускается только без секретных значений; сейчас для запуска ключи не нужны.

Дополнительные ZIP-копии, выгрузки JSON из демо и новые дублирующие результаты хранить в игнорируемых `exports/` или `diagnostics/local_runs/`. Существующие снимок, эксперимент и отчёты никуда не перемещены и не удалены. Служебный `BEEGROWTH_CODEX_NEXT_STEP.md` в команды ниже не включён: он не нужен для запуска или проверки проекта.

Историческая проверка отслеживаемых и доступных для добавления текстовых файлов не обнаружила типичных шаблонов API-ключей и заголовков закрытых ключей. Это ограниченная проверка, её область записана в [git_scan.json](diagnostics/submission_prep/git_scan.json). Перед отправкой повторно проверяются состав и содержимое подготовленного коммита; локальные секреты сохраняются на компьютере и не включаются в Git.

## Локальный коммит и отложенная отправка

Используются ветка `main`, upstream `origin/main` и уже настроенный remote `origin`: `https://github.com/BAITC-Hacks/hack-1c50feda-yassawi`. При проверке удалённая `main` оказалась на коммите `b14878ea79b376acaa12e274355b8f243e198430`, на один коммит впереди исходной локальной версии. Новые изменения команды QADAM затрагивают агента, демо и тесты.

Пользователь выбрал **сохранить проверенный коммит локально и отложить отправку до согласования с командой**. Поэтому push и интеграция удалённых изменений не входят в текущее завершение работы. Проверенный локальный `agent.py` сохраняет контрольный SHA-256; существующий remote не меняется.

Ниже зафиксирована область подготовки локального коммита из корня проекта в PowerShell. Это справочная запись процесса, а не требование повторять уже выполненный коммит:

```powershell
git add -- .gitattributes .gitignore README.md DEMO.md SUBMISSION.md agent.py submission.csv requirements.txt organizer_hashes.json demo_app.py tests
git add -- split_eval.py render_stage1_report.py stabilization_audit.py diagnostics snapshots/before_stage1 experiments/stage1_expanded_search
git diff --cached --check
git diff --cached --stat
git status --short
git diff --cached
git commit -m "Finalize BeeGrowth Agent: verified submission, demo and README"
git rev-parse HEAD
```

Перед `git commit` проверяются состав и содержимое подготовленной разницы. `git add .` не используется, чтобы не захватить служебные заметки. Фактический хеш локального коммита указывается в итоговом сообщении по выполненной задаче. Этот документ не подтверждает публикацию в удалённом репозитории. После будущего согласования и интеграции потребуется обычная отправка и проверка удалённого хеша; `--force` не используется.

Официальный одиночный прогон дал PASS и net +13 742 после округления; на seed 0–9 все 10 результатов положительны, медиана 312 816. Повторная раздельная оценка подтвердила соблюдение лимитов, отсутствие падений, отброшенных и обрезанных кампаний на тех же seed; вклад финала на seed=42 составляет −4381.58. Две официальные генерации CSV совпали побайтово. `pip check` прошёл, локальный сервер демо вернул HTTP 200 для страницы и health endpoint; сценарий AppTest подтвердил интерфейс и генерацию официального CSV. [Исторический протокол](diagnostics/submission_prep/completeness.json). Исходные CSV и исторические отчёты сохранены. Локальная техническая готовность подтверждена; отправка коммита отложена до согласования новых изменений команды.
