# Кейс талдауы және қабылданған шешімдер

Негіз: пайдаланушы берген алты беттік HackAlem AI Beeline Tariff Marketing Campaigns Case және Downloads-та табылған сәйкес қатысушы пакеті. Құжат талаптары өнім спецификациясы ретінде қолданылды; олар чаттағы пайдаланушы нұсқауын алмастырмайды.

## Нақты проблема

«Кім тариф ауыстырады?» деген болжам жеткіліксіз. Ауысу downsell-ге әкелуі мүмкін, ал байланыс қымбат. Сондықтан мақсат — ауысу саны емес, **бірегей абоненттердегі ARPU өсімі минус барлық байланыс шығыны**.

Бірдей пайыздық өсім бастапқы ARPU жоғары абонентте көбірек ақша әкеледі. Бірақ жоғары ARPU-ы бар аудитория міндетті түрде тиімді бағыт емес: тарих басқа популяцияға қатысты. Осы айырмашылықты пилот арқылы тексеру керек.

Қатысушы дерегінде 23 441 профиль және 14 823 тарихи жол бар. PDF тарихты 14 824 деп көрсетеді; интерфейс нақты CSV жолдарын санайды. 21 тариф және 4 канал бар. Baseline нақты `predicted_arpu` сомасынан есептеледі, PDF-тегі дөңгелектелген сан hardcode жасалмайды.

Дерек сапасы: current_tariff бағанында 95, arpu_segment бағанында 5, data_segment бағанында 110 бос ұяшық бар. ID қайталанбайды, predicted_arpu жарамды. Агент белгісіз тариф/сегментті ойдан толтырмайды; көрсетілген сүзгілермен жарамды топ құра алмайтын профильдерді жоспардан шығарып, есепте санын көрсетеді. Dashboard «дерек сапасы» көрсеткішінде міндетті бағандардағы 100 бос ұяшықты көрсетеді; бұл міндетті түрде 100 түрлі адам деген сөз емес.

## Неліктен қарапайым тәсіл жеткіліксіз

| Тәсіл | Әлсіздігі | QADAM шешімі |
|---|---|---|
| Ең жоғары тарихи өсімді таңдау | Деректер басқа аудиториядан | Тарих гипотезаларды ғана ранжирлейді |
| Бір кішкентай пилотты ақиқат санау | Шу әсерінен белгі ауысады | Posterior shrinkage, үлгі көлемі, қайта сынау |
| Барлығына call жіберу | 100 000 бюджет небәрі 625 контактке жетеді | Каналдың таза шекті құнын салыстыру |
| Push тегін болғандықтан барлығына жіберу | Тегін контакт те downsell және контакт лимитін тудырады | Теріс/сенімсіз сегменттерді өткізіп жіберу |
| Бір сәтті сегментті қайталау | Бірегей эффект қайталанбайды, контакт ақысы қалады | Финалдық сегменттердің қиылыспауын сақтау |
| Барлық 20 пилотты алдын ала бекіту | Алынған дәлелге жауап бермейді | Барлау → қайта бағалау → бағытты өзгерту |

## Архитектура

`customer_profile + public tariffs/channels + observable history → candidate ranking → env.run_pilot → posterior → budget-aware portfolio → list[dict]`

Dashboard агентті өзгертпейді: сол `Agent` ресми `evaluate_agent` арқылы орындалады. Нәтиже local JSON-ға атомарлы сақталады, интерфейс тек агрегаттарды көрсетеді. Жасырын scorer нәтижесі agent.act орындалғаннан кейін ғана dashboard-қа түседі және шешімге кері берілмейді.

## Формулалар

Тарихта `r = (after - before) / before`, `before > 100`, `r ∈ [-1,2]` шектеуі өте шағын бөлгіштер мен outlier әсерін азайтады. Ранжирлеу бағасы `mean(r) × n/(n+25) - 0.3/sqrt(n)`; ол тасымалданатын нақты эффект ретінде қолданылмайды.

Пилотта канал эффекті базалық шкалаға `y = observed_lift_ratio / multiplier` арқылы ауысады. Әлсіз prior `N(0, 0.5²)`. Бақылау дисперсиясының жорамалы `v = 0.9² / (n × multiplier²)`. Posterior precision `1/0.5² + Σ(1/v)`; орташа `Σ(y/v) / precision`; стандарттық қате `sqrt(1/precision)`.

Канал бойынша сақ финалдық бағалау:

```text
lower_gain = (posterior_mean - z × posterior_se)
             × channel_multiplier × segment_total_predicted_arpu
             - segment_size × channel_cost
```

Нөлден төмен бағаланған бағыттар оң портфельге кірмейді. «Кемінде бір науқан» талабы мен теріс әсер қаупі қайшылыққа түскенде жүйе fallback-ты ескертумен көрсетеді.

Бұл модельге тәуелді сақ баға; adaptive selection, үлгілердің ықтимал қиылысуы және distribution shift салдарынан ол кепілді статистикалық lower confidence bound емес. Бағалау жорамалдары README-де ашық жазылған.

## Ресурс есебі

Әр пилот алдында public `remaining_budget`, `remaining_contacts`, `pilots_left` оқылады. Пилоттан кейінгі қалған ресурстардан финалдық жоспар құрылады. Портфельдің қарастырылған күйлері нақты ақшамен және контакт санымен тексеріледі. Іздеуде ресурстық bucket тек pruning үшін қолданылады; feasibility дөңгелектелмейді.

Пилот пен финалдық аудитория арасында қабаттасу болуы мүмкін. Сондықтан dashboard-та көрсетілген нақты net ресми scorer-дан алынады. Жеке науқанның модельдік болжамы нақты mock баллмен араластырылмайды.

## Талаптарға сәйкестік

| Талап | Іске асуы |
|---|---|
| `Agent.act(env)` | `agent.py`, сыртқы API/LLM жоқ |
| Пилоттар және олардан үйрену | Public run_pilot; әр бақылаудан кейін posterior жаңарады |
| ≤20 пилот, 10–200 адам | Әр шақыру алдындағы шектеулер |
| ≤10 науқан, ≤5000 аудитория | Disjoint cells + portfolio feasibility |
| 100 000 бюджет, 15 000 контакт | Пилоттардан кейін қалған нақты ресурстар |
| Бірегей абоненттің әсері | Финалдық сегменттер қиылыспайды; scorer жалпы дедупликациялайды |
| `submission.csv` | Өзгертілмеген `make_submission.py`, seed42 |
| 10 минуттан аспау | Пилот цикліне 240 секунд guard; нақты жергілікті прогон шамамен 1 секунд |
| Түсінікті интерфейс | Бес бөлім, шешім паспорты, CSV/JSON, seed/сақтық баптауы |
| Қайталану | Белгіленген dependency нұсқалары, deterministic tie-break, seed |

## Шынайы келесі зерттеу қадамдары

Канал ауысуының сызықтық жорамалын бөлек randomized пилоттармен тексеру; noisy pilot үшін сенімді variance estimate API сұрау; қалдық тәуелділікті модельдеу; бөлек уақыт/популяция тестінде тәуекел деңгейін калибрлеу. Жасырын judge нәтижесін көрмей, осы жеткізілімді финалдық optimum деп атауға болмайды.

Ұсынылатын қорғау сөзі: «Біз тарихи корреляцияны пайда деп қабылдамаймыз. QADAM алдымен оның жаңа аудиторияда жұмыс істейтінін тексереді, содан кейін белгісіздікті ақша және контакт лимитімен бірге есептейді. Аналитик әр шешімнің негізін көре алады».
